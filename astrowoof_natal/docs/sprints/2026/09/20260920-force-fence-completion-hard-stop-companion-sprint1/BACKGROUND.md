# Background — force-fence completion hard-stop companion

## Objective

Partner with API to turn the existing safe active-run force fence into a useful,
strictly evidence-bound operator hard-stop completion path. The completed
operation may move a run to `operator_quarantined` and release only local API
capacity **only** after SBE supplies exact safe-boundary evidence.

The existing cooperative suspension work is foundation, not the complete
operator workflow: its qualified scope deliberately included zero resource
release and no inferred process exit or native terminal result.

## Required stance

SBE must never make an unsupported, stale, ambiguous, or merely silent active
route look safely quarantinable. Those cases need a typed unresolved/deferred
result that directs an exact next containment/exit observation. It does not,
by itself, authorize API capacity release. Native/provider/workspace/spend
evidence may remain only as non-scheduling retained custody after a final
completion is truthfully established.

## Non-negotiable peer-progress invariant

For every final hard-stop outcome, including unsupported or ambiguous routes,
an otherwise eligible peer must be able to claim and run normally after API's
completion transaction. SBE must therefore distinguish facts that require
retention for truth/audit from any fact that grants or requires local execution
capacity. SBE never releases API resources itself, but its result contract must
be sufficient for API to do so without inference.

An unresolved result is not a final completion if the native child may still
be alive. It must identify the exact safe-stop/exit observation or supported
containment escalation needed before API releases local capacity. Silence,
timeout, or missing evidence never proves that boundary. The final
capacity-releasing proof classes are: (1) a cooperative SBE safe-stop result
bound to the exact request and invocation, (2) an API-parent-owned,
exact-supervised child/process-group exit observation, or (3) an
API/platform-proven worker replacement bound to old-boot retirement/no-overlap
and new-boot evidence. SBE cannot manufacture either API-owned proof.

If in-process proof cannot be obtained, API may use a separately audited SBE
worker replacement as the operational stop. SBE's contract must make the old
worker/child identity and any collateral active-child inventory observable so
API does not silently discard another run while isolating the target.
