# 2026-08-04 Cleanup Sprint 1

## Purpose

Close small, already-decided follow-ups from the editorial-quality sprint
without reopening product architecture. The sprint contains four bounded
slices and should leave production behavior more legible, authoring guidance
more precise, QA warnings more trustworthy, and completed-run storage safer.

## Slice 1 — Dynamic-chapter contract closure

- Publish one durable v0.4 contract for dynamic chapter registries.
- Reconcile superseded open questions in the Ella UI decision record.
- Preserve backward compatibility and frontend fallback as distinct concerns.

## Slice 2 — Subtitle craft guidance

- Carry the first live Ella lesson into pass-6 authoring instructions.
- Prefer direct reader orientation and varied sentence movement.
- Avoid brittle lexical rejection rules.
- Verify the guidance appears only where dynamic chapters are authored.

## Slice 3 — No-astrology advisory audit

- Inventory warnings in preserved reference decks.
- Classify sampled warnings as true, false, or ambiguous.
- Refine only demonstrably overbroad triggers.
- Add focused regression coverage and retain uncertainty as advisory.

## Slice 4 — Completed-run retention hygiene

- Define resumable versus completed-run retention requirements.
- Add a safe, explicit cleanup/archive operation for completed runs only.
- Preserve delivery, state, accounting, QA, retry evidence, and accepted prose.
- Remove only reproducible or duplicate expanded working material.
- Test refusal, dry-run, idempotence, and retained-artifact integrity.

## Exit criteria

- All four slices are implemented and documented.
- Focused and full regression suites pass.
- No live OpenAI request is required unless a code result cannot be established
  deterministically.
- The sprint log records decisions, evidence, and remaining exclusions.
