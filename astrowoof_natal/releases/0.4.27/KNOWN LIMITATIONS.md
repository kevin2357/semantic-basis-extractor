# SBE 0.4.27 Known Limitations

- The two happy-path witnesses begin at a production-shaped post-fan-in boundary.
  Their machine-readable precursor inventories identify fixture-installed facts.
- They do not prove end-to-end provider-output evaluation, QA acceptance, natural
  successor creation, product-policy selection, API reader delivery, or an
  exhaustive state space.
- Ordinary external-authority v2 Batch dispatch remains deliberately deferred.
- Qualification evidence never authorizes scheduling, provider creation, spending,
  reservation release, billing settlement, or publication.
- API deployment requires a digest-pinned worker image and fresh immutable
  generation-profile binding after publication.

## Retained cohort posture

Strudel/Princess were not accessed or mutated during this sprint. The release
candidate provides supported commands and evidence needed for a separately
authorized recovery assessment, but does not itself authorize recovery.

Any retained-run action requires all of:

1. the immutable released wheel pinned by exact SHA-256;
2. independently attested API and worker compatibility/profile identities;
3. complete snapshot validation at the stable logical root;
4. current lifecycle inspection and exact provider-identity reconciliation;
5. proof that the selected path permits no duplicate provider create; and
6. separate owner/API authorization for the specific retained run.
